# 🤖 Python Agents Explained

## Overview

The Job Application Assistant uses **3 autonomous AI agents** written in Python that work independently to help users with job applications. Each agent runs continuously, performing specific tasks every 5 minutes.

---

## 🎯 What Each Agent Does

### Agent 1: Job Hunter (OpenAI GPT-4)

**Purpose**: Find and score job matches for users

**What it does each iteration**:

1. **Fetches User Profile**
   - Gets user's skills, experience, education, location, target role
   - Example: "samuel_student" with skills: Python, SQL, Data Analysis

2. **Retrieves Job Listings**
   - Fetches up to 50 active job listings from database
   - Filters by active status (`is_active = true`)

3. **Scores Each Job (0-100)**
   - Uses OpenAI GPT-4 to analyze:
     - Skills match (required vs user's skills)
     - Location preference
     - Salary range compatibility
     - Experience level alignment
   - Example output:
     ```
     Job: "Data Analyst at DataCo"
     Score: 85/100
     Reasoning: "Strong match - user has Python and SQL skills, 
                 location matches, salary range appropriate"
     ```

4. **Creates Recommendations**
   - If score >= 60, saves to `job_recommendations` table
   - Stores match score, reasoning, and status ('pending')

5. **Generates Market Insights**
   - Analyzes job trends:
     - Top skills in demand
     - Most common locations
     - Experience level distribution
   - Saves insights to `agent_insights` table

**Example Output**:
```
🔍 Job Hunter (openai) - Turn 1
  👤 Analyzing profile for: Samuel Widmer
  📋 Found 50 job listings
  🤔 Scoring: Data Analyst at DataCo...
  ✅ Recommended (85/100): Data Analyst
     Reasoning: Strong match - user has Python and SQL skills...
  🤔 Scoring: Software Engineer at TechCorp...
  ⏭️  Skipped (45/100): Software Engineer
  ✅ Turn complete! Scored 50 jobs, recommended 12
  📊 Market insights generated
```

### Agent 2: CV Crafter (Anthropic Claude 3.5 Sonnet)

**Purpose**: Generate tailored CVs and cover letters for job applications

**What it does each iteration**:

1. **Finds Draft Applications**
   - Searches for applications with `status = 'draft'`
   - These are jobs the user wants to apply to but hasn't prepared documents for

2. **Gets User Profile & Job Details**
   - Retrieves user's complete profile (skills, experience, education)
   - Fetches full job description and requirements

3. **Generates Tailored CV**
   - Uses Claude to create a CV specifically optimized for that job:
     - Highlights relevant skills
     - Emphasizes matching experience
     - Formats professionally
   - Saves to `generated_cvs` table with version tracking

4. **Generates Cover Letter**
   - Creates a personalized cover letter:
     - Addresses specific job requirements
     - Explains why user is a good fit
     - Professional tone
   - Saves to `cover_letters` table

5. **Analyzes Skill Gaps**
   - Compares user's skills vs job requirements:
     - Missing required skills
     - Missing preferred skills
   - Creates insight: "Consider learning React to improve match"

6. **Updates Application Status**
   - Changes status from `'draft'` → `'ready_to_submit'`
   - Adds note: "CV and cover letter generated by CV Crafter"

**Example Output**:
```
📝 CV Crafter (anthropic) - Turn 1
  📋 Found 2 draft application(s)
  🔨 Processing application #5 for: Data Analyst
  ✨ Generating tailored CV...
  ✅ CV generated (version 1)
  ✨ Generating cover letter...
  ✅ Cover letter generated (version 1)
  📊 Skill gap analysis completed
  ✅ Application status updated to 'ready_to_submit'
  ✅ Turn complete! Processed 2 application(s)
```

### Agent 3: Application Tracker (Grok Beta)

**Purpose**: Monitor applications and generate insights

**What it does each iteration**:

1. **Fetches All Applications**
   - Gets all applications for the user (all statuses)
   - Statuses: draft, ready_to_submit, submitted, under_review, interview, offer, rejected, withdrawn

2. **Identifies Stale Applications**
   - Finds applications with no updates for 7+ days
   - Excludes rejected/withdrawn applications
   - Example: Application submitted 10 days ago, still "under_review"

3. **Calculates Success Metrics**
   - Success rate: `(offers / submitted) * 100`
   - Status breakdown: counts per status
   - Example:
     ```
     Total: 15 applications
     Submitted: 12
     Offers: 2
     Success Rate: 16.67%
     Status Breakdown: {submitted: 5, under_review: 3, interview: 2, offer: 2, rejected: 3}
     ```

4. **Analyzes Patterns with LLM**
   - Uses Grok to analyze application data:
     - Common rejection reasons
     - Best performing application types
     - Time-to-response patterns
   - Generates insights like:
     - "Applications to startups have 30% higher response rate"
     - "Remote positions take 2x longer to respond"

5. **Generates Follow-up Reminders**
   - For each stale application, creates a reminder:
     ```
     Follow-up Reminder:
     Application for Data Analyst at DataCo has been under_review for 10 days.
     Consider following up with the employer to check on status.
     ```
   - Saves to `agent_insights` table

**Example Output**:
```
📊 Application Tracker (grok) - Turn 1
  📋 Found 15 total application(s)
  ⏰ Found 3 stale application(s)
  📈 Success rate: 16.67%
  📊 Status breakdown: {'submitted': 5, 'under_review': 3, 'interview': 2, 'offer': 2, 'rejected': 3}
  💡 Generated 2 insight(s)
  📧 Generated 3 follow-up reminder(s)
  ✅ Turn complete!
```

## 🔒 Sandboxing Implementation

### What is Sandboxing?

Sandboxing isolates tool execution in Docker containers to prevent malicious code from accessing your system. Think of it as a "jail" for code execution.

### How It Works

#### Architecture

```
┌─────────────────────────────────────────┐
│  Python Agent (Main Process)           │
│  - job_hunter_agent.py                  │
│  - cv_crafter_agent.py                  │
│  - application_tracker_agent.py          │
└──────────────┬──────────────────────────┘
               │
               │ Tool Call (e.g., add_recommendation)
               │
               v
┌─────────────────────────────────────────┐
│  SandboxedJobToolsWrapper                │
│  - job_sandbox_tools.py                  │
│  - Checks if sandbox is enabled          │
└──────────────┬──────────────────────────┘
               │
               ├─→ Sandbox OFF: Execute directly
               │   (fast, no isolation)
               │
               └─→ Sandbox ON: Route through Docker
                   │
                   v
┌─────────────────────────────────────────┐
│  AgentBound SDK                          │
│  - mcp_sandbox_openai_sdk                │
│  - Creates Docker container              │
└──────────────┬──────────────────────────┘
               │
               v
┌─────────────────────────────────────────┐
│  Docker Container (Ephemeral)            │
│  ┌──────────────────────────────────┐   │
│  │  job_mcp_server.py                │   │
│  │  - JSON-RPC server                │   │
│  │  - Receives tool calls            │   │
│  │  - Executes in isolation          │   │
│  └──────────────────────────────────┘   │
│                                           │
│  Permissions:                             │
│  - Filesystem: Only workspace dir          │
│  - Network: Only LLM APIs                 │
│  - Environment: Explicit vars only        │
└───────────────────────────────────────────┘
```

### Sandbox Features

#### 1. **Process Isolation**
- Each tool call runs in a separate Docker container
- If something goes wrong, it can't affect the main process
- Container is destroyed after execution

#### 2. **Filesystem Restrictions**
- Only workspace directory (`/Users/samuelwidmer/Desktop/codingwithai`) is accessible
- Read/write permissions limited to this directory
- Cannot access `/etc`, `/home`, or other system directories

#### 3. **Network Allowlist**
- Only approved domains can be accessed:
  - `api.openai.com:443` (OpenAI API)
  - `api.anthropic.com:443` (Anthropic API)
  - `api.x.ai:443` (Grok API)
- Cannot access random websites or make unauthorized API calls

#### 4. **Environment Variable Control**
- Only explicitly allowed variables are passed:
  - `OPENAI_API_KEY`
  - `ANTHROPIC_API_KEY`
  - `GROK_API_KEY`
  - `DATABASE_URL`
- Cannot access other environment variables

#### 5. **Ephemeral Containers**
- Container is created, used, then destroyed
- No persistent state between tool calls
- Prevents data leakage

### Code Flow

#### Without Sandbox (Default)

```python
# In agent code (e.g., job_hunter_agent.py)
if self.sandbox_tools:
    # Sandbox enabled
    await self.sandbox_tools.execute_sandboxed(
        "add_recommendation",
        {
            "user_id": user_id,
            "job_id": job_id,
            "match_score": score,
            "reasoning": reasoning,
        },
        self.db_client,
    )
else:
    # Direct execution (fast)
    await self.db_client.add_recommendation(
        user_id, job_id, score, reasoning
    )
```

#### With Sandbox Enabled

```python
# In job_sandbox_tools.py
async def execute_sandboxed(self, tool_name, tool_input, db_client):
    # 1. Connect to Docker container (first time only)
    if not self.server_connected:
        await self.mcp_server.connect()  # Starts Docker container
    
    # 2. Send JSON-RPC request to container
    result = await self.mcp_server.call_tool(tool_name, tool_input)
    
    # 3. Container executes tool in isolation
    # 4. Result returned to agent
    return result
```

### MCP Server in Container

The `job_mcp_server.py` runs inside the Docker container and handles tool calls:

```python
# job_mcp_server.py (runs in Docker)
def handle_call_tool(id, tool_name, arguments):
    # Tool executes here, isolated from host system
    result = {
        "status": "success",
        "tool": tool_name,
        "arguments": arguments,
    }
    return result
```

### Enabling Sandboxing

**Option 1: Environment Variable**
```bash
USE_SANDBOX=true python scripts/run_job_agents.py
```

**Option 2: npm Script**
```bash
npm run agents:python:sandbox
```

**Option 3: In Code**
```python
# In run_job_agents.py
use_sandbox = os.environ.get("USE_SANDBOX", "false").lower() == "true"

job_hunter = JobHunterAgent(
    job_hunter_config, 
    llm_manager, 
    use_sandbox=use_sandbox  # Enable sandbox
)
```

### Fallback Behavior

If sandbox initialization fails (Docker not running, SDK not installed), agents automatically fall back to in-process execution:

```python
# In job_sandbox_tools.py
if not self.sandbox_initialized:
    # Fallback: execute directly
    return await self._execute_in_process(tool_name, tool_input, db_client)
```

This ensures agents always work, even without sandboxing.

   ```

   user_profile = await db_client.get_user_profile("samuel_student")

   ```

3. **Gets Job Listings**
   ```python
   jobs = await db_client.get_job_listings(50)
   # Returns: List of 50 active jobs
   ```

4. **Scores Each Job** (with sandbox)
   ```python
   # LLM call (outside sandbox - safe)
   score_result = llm_manager.score_job_match("openai", "gpt-4", profile, job)
   # Returns: {score: 85, reasoning: "Strong match..."}
   
   # Database write (inside sandbox - protected)
   if score_result.score >= 60:
       await sandbox_tools.execute_sandboxed(
           "add_recommendation",
           {...},
           db_client
       )
   ```

5. **Sandbox Execution** (if enabled)
   ```
   [Sandbox] Connecting to MCP server in Docker container...
   [Sandbox] MCP server connected successfully
   [Sandbox] Executing add_recommendation in Docker container
   ```

6. **Result**
   ```
   ✅ Recommended (85/100): Data Analyst at DataCo
   ```

## 🛡️ Security Benefits

1. **Prevents Code Injection**: Malicious code in tool inputs can't escape container
2. **Limits Data Access**: Can only access approved filesystem paths
3. **Network Isolation**: Can't make unauthorized API calls
4. **Environment Protection**: Can't read sensitive environment variables
5. **Process Isolation**: Container crash doesn't affect main process

## 📝 Summary

- **3 Agents**: Job Hunter, CV Crafter, Application Tracker
- **Each runs independently** every 5 minutes
- **Sandboxing optional**: Enabled with `USE_SANDBOX=true`
- **Docker isolation**: Tool calls execute in ephemeral containers
- **Automatic fallback**: Works without sandbox if Docker unavailable
- **Security**: Filesystem, network, and environment restrictions

The agents work autonomously to help users find jobs, prepare applications, and track progress—all while maintaining security through optional sandboxing.
